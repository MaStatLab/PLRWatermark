# Reproduction workflows

These commands are adapted from the original project's reproduction guide.
Run from the repository root with the pinned environment and verified
external benchmark inputs described in `README.md`. Work in a separate copy
of the repository: the principal analysis commands write to their default
result paths and replace the corresponding outputs in that copy. Preserve
the supplied snapshot and its checksums unchanged. The technical report,
including its supplement, is included as a compiled PDF with matching TeX
source and bibliography.

Fresh computations may differ from historical records, particularly for
language-model outputs whose generation provenance is incomplete. Record
the interpreter, dependency versions, hardware, code identity, seeds, and
output paths. Current file hashes do not certify that the current code
generated older arrays.

## Principal artifact-generation order

This is the main simulation, reanalysis, and plotting workflow, not a claim
that every historical or exploratory JSON file is regenerated by one recipe.
Additional diagnostic configurations are described in `code/README.md` and
the files' own metadata. Production simulations and bootstrap analyses can
take substantial time. The commands below do not run new language-model
generation; they analyze the stored arrays where indicated.

```sh
export PYTHONDONTWRITEBYTECODE=1
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
export MPLCONFIGDIR="$PWD/tmp/matplotlib"

# Record the new working-copy environment before computation.
python --version
python -m pip show numpy scipy matplotlib torch transformers ipython
python code/write_provenance.py

# Clean synthetic benchmark and numerical/posterior diagnostics.
python code/benchmark_paper_experiment.py
python code/paired_comparisons.py
python code/check_clean_quadrature.py
python code/check_delta_learning.py
python code/check_block_posterior.py
python code/regime_sweep.py
python code/tail_regime_sweep.py

# Contamination and the additional inverse-transform support diagnostic.
python code/benchmark_contamination.py
python code/check_contamination_quadrature.py
python code/contamination_asymmetry.py
python code/inverse_support_edge.py

# Archived benchmark reanalysis, family fitting, and prefix curves.
python code/estimate_tail_width.py
python code/real_data_experiment.py
python code/real_data_experiment.py --delta-low 0 --delta-high .1 \
    --results-dir results/bayesian_paper_benchmark/real_model/sensitivity_uniform_0_0p1
python code/real_data_prefix_curves.py

# Analyze the stored temperature-matched arrays; do not regenerate them.
export WM_SCRATCH="$PWD/results/bayesian_paper_benchmark/real_model/temperature_matched"
python code/analyse_temperature_matched.py --allow-legacy-archives
python code/plot_temperature_prefix_curves.py --allow-legacy-archives
python code/summarise_empirical_deficits.py --allow-legacy-archives
python code/delong_prompt_bootstrap.py --allow-legacy-archives
python code/delong_prompt_bootstrap.py --allow-legacy-archives --prompt-start 500 \
    --output "$WM_SCRATCH/delong_tests_holdout.json"
python code/pivot_repetition.py

# Hierarchical extensions and their paired decision-based regret summaries.
python code/deficit_persistence_sweep.py
python code/width_persistence_sweep.py
python code/pooling_max_regret.py --write
python code/pooled_width_real_data.py --allow-legacy-archives

# Refresh the actual Gumbel-only figure overrides used by the manuscript.
python code/make_gumbel_only_figures.py
```

`analyse_temperature_matched.py` is the legacy base-only split-half
diagnostic. It is not the combined 2,500-document prefix/bootstrap analysis.
The holdout bootstrap above uses only the 2,000 extension prompts. The
inverse diagnostic and alternate-prior outputs are included for completeness
and do not extend the manuscript's current Gumbel-only claims.

After a rerun, inspect numerical differences with `code/diff_artifacts.py`
before drawing conclusions. An updated publication snapshot requires fresh
integrity metadata; do not represent the old `FILE_INDEX.json` or
`SHA256SUMS` as covering modified files.

## Technical-report checks and compilation

The included source at `manuscript/bayesian_pivot_watermark_gumbel.tex`
matches the technical-report date in `README.md`. Its original relative
figure paths must be preserved. The seven external figures are under
`results/`; the three graphical-model figures are inline TikZ.

The read-only 498-check manuscript audit is:

```sh
python code/check_manuscript_tables.py
```

The full test suite additionally needs the checksum-verified benchmark
tensors and clean pinned sampler checkout described in `README.md`. Neither
the audit nor these tests regenerates the underlying scientific experiments.

To compile the included source, use a TeX Live installation with pdfLaTeX
and the packages named in the source. Run three passes **in a separate
working copy**. The supplied `.bbl` avoids a bibliography-generation step;
shell execution is disabled:

```sh
cd manuscript
pdflatex -no-shell-escape -interaction=nonstopmode -halt-on-error bayesian_pivot_watermark_gumbel.tex
pdflatex -no-shell-escape -interaction=nonstopmode -halt-on-error bayesian_pivot_watermark_gumbel.tex
pdflatex -no-shell-escape -interaction=nonstopmode -halt-on-error bayesian_pivot_watermark_gumbel.tex
cd ..
```

The new PDF and TeX intermediates remain under `manuscript/` and are ignored
by Git. The distributed PDF is
`output/pdf/bayesian_pivot_watermark_gumbel.pdf`; compilation does not replace
it automatically. Inspect the compiled output and check for unresolved
citations or references before replacing that distribution file.

## Author-only revision workflow

Authors revising the report can use the following **only in a separate
working copy**. The first two commands modify the manuscript; they are not
needed to analyze the supplied data:

```sh
python code/update_manuscript_table_mcse.py
python code/sync_manuscript_tables.py
python code/check_manuscript_tables.py

```

These scripts do not replace statistical review of changed estimates or
conclusions. Compile using the three-pass commands above. Preserve the
supplied snapshot while revising; after review, update the intended source
and final PDF together, then refresh provenance and integrity metadata for a
new distribution. Git ignores other working drafts and build intermediates.

## Fresh matched-arm generation

Generation requires model weights, tokenizers, pinned C4 records, appropriate
access, and much more computation than stored-array analysis. This recipe
creates new temporary output paths and never resumes or overwrites the
historical generation archives. The current generator cannot retroactively
establish their original generation settings.

```sh
WM_FRAMEWORK_PARENT=$(mktemp -d)
git clone --filter=blob:none --no-checkout \
    https://github.com/lx10077/WatermarkFramework.git \
    "$WM_FRAMEWORK_PARENT/WatermarkFramework"
git -C "$WM_FRAMEWORK_PARENT/WatermarkFramework" sparse-checkout set --no-cone \
    '/real data/sampling.py' '/real data/alternative_prf_schemes.py'
git -C "$WM_FRAMEWORK_PARENT/WatermarkFramework" checkout --detach \
    05b7ffda9279fc9e645f38807e4a0e2dbcff4330
export WATERMARK_FRAMEWORK_DIR="$WM_FRAMEWORK_PARENT/WatermarkFramework"
export PYTHONDONTWRITEBYTECODE=1

WM_REGEN=$(mktemp -d)
mkdir -p "$WM_REGEN/extension"
for model in 1p3B 2p7B; do
  python code/generate_temperature_matched.py --model "$model" \
      --batch 25 --device auto --temps 0.1,0.2,0.3 --tokens 200 \
      --out "$WM_REGEN/matched_${model}_lo.npz"
  python code/generate_temperature_matched.py --model "$model" \
      --batch 25 --device auto --temps 0.4,0.5,0.6,0.7,1.0 --tokens 100 \
      --out "$WM_REGEN/matched_${model}_hi.npz"

  # The first 500 rows reproduce this model's benchmark prompt tensor;
  # the pinned C4 shard and tokenizer supply 2,000 additional prompts.
  python code/build_prompts.py --model "$model" \
      --out "$WM_REGEN/extension/prompts_${model}.npy"
  python code/generate_temperature_matched.py --model "$model" \
      --batch 25 --device auto --temps 0.2,0.3 --documents 2000 \
      --prompts "$WM_REGEN/extension/prompts_${model}.npy" \
      --prompt-offset 500 --tokens 200 \
      --out "$WM_REGEN/extension/ext_${model}_lo.npz"
  python code/generate_temperature_matched.py --model "$model" \
      --batch 25 --device auto --temps 0.4,0.5 --documents 2000 \
      --prompts "$WM_REGEN/extension/prompts_${model}.npy" \
      --prompt-offset 500 --tokens 100 \
      --out "$WM_REGEN/extension/ext_${model}_hi.npz"
done

# Analyze the fresh run without replacing the manuscript's records.
WM_SCRATCH="$WM_REGEN" python code/analyse_temperature_matched.py
python code/plot_temperature_prefix_curves.py --scratch "$WM_REGEN" \
    --output-dir "$WM_REGEN/analysis"
```

`--device auto` selects CUDA, then MPS, then CPU. Explicitly requesting an
unavailable device fails. Generation uses float32. Raw-arm random streams
are derived per global prompt index and prompt-row digest, so current
base/extension runs do not restart the same stream. Model arithmetic can
still depend on batch size; retain the batch size, seed, device, software
versions, and model revision in a rerun record.

The schema-v3 run records enforce model, prompts, shape, seed, batch, device,
and code/software compatibility before resuming. Retain each prompt table's
JSON sidecar and keep the pinned sampler checkout clean. A changed run or a
metadata-free historical file requires a new output path. The analysis
loader checks array hashes, prompt digests, row identities, and disjoint
offsets again. Fresh schema-v3 runs do not use `--allow-legacy-archives`.

The historical files remain subject to the article's limitations: they do
not establish whether an earlier recipe that reused a raw random stream
across base and extension blocks was used. Existing prompt-cluster
uncertainty estimates assume independent raw generation across prompts.
Corrected current code does not retrospectively verify that assumption.
